Findings:
- `M1` MINOR `README.md:252-254`, `CHANGELOG.md:18`, `capture.sh:178`. These say "the window
  opens off screen unless CAPTURE_VISIBLE=1" as a fact. The header (`capture.sh:31-41`) says
  desktop display servers clamp the position back into the screen. My reading of Godot 4's
  `_create_window` is that it clamps to `usable_rect.end - size/3`. **Failure scenario:** on a
  1920x1080 macOS laptop, the default leaves a 384x216 corner of the window on screen. It still
  takes focus. An agent's operator reads the CHANGELOG, expects nothing on screen, and #37
  closes while its complaint (focus theft) still happens. **Fix:** say "toward off screen (macOS
  and Windows clamp about a third of the window on screen; focus is not suppressed)" at all three
  sites. Also keep #37 open, or split out its focus half. The brief's fallback, "the smallest
  documented mechanism that keeps the window from taking focus", was named and not applied. That
  was a defensible call: the wrapper does not write project files. But it needs a disposition,
  not silence.
- `N1` NIT `capture.sh:31-37`. d642d12 left a 145-column comment line. It also contradicts the
  line before it. "CLAMP … into the screen's usable rect" means the whole window is visible.
  "A clamp there leaves most of the window past the edge" means it is not. Say "clamped so about
  a third stays on screen", then wrap.
- `N2` NIT `capture.sh:178`. The WARN says "(off screen unless CAPTURE_VISIBLE=1)" even on a run
  that set `CAPTURE_VISIBLE=1`.
- `N3` NIT `capture.sh:281-318`. The end-to-end self-test cases inherit the caller's
  `GDK_CAPTURE_REPORT_DIR`. `GDK_CAPTURE_REPORT_DIR=. capture.sh --self-test` reports 3 of 17
  MISS, and a `No such file` from line 308. The value is invalid, so red is not wrong, but the
  MISS text blames rotation. Pin it in the inner `env` the way `GDK_CAPTURE_POSITION` is pinned.
- `N4` NIT `capture.sh:277`. `for i in $(seq 1 60); do record_run …` is 120 spawns. The self-test
  went from 0.09 s to 1.66 s. The runners tier is parallel, so this is off the critical path.
  One `printf` of 60 lines, then one `record_run`, proves the same trim.
- `N5` NIT `capture.sh:407-411`. With `previous` present as a file, the refusal says "could not
  move .capture-reports/eyes.png". There was no `eyes.png`; the `mkdir` failed. Name the path
  that failed.
- `N6` NIT proof budget. It asked for 5-6 cases; 7 landed (3 rotation, 1 loop, 3 end to end). Each
  one is load-bearing on a mutant or a brief row, so none should go.
