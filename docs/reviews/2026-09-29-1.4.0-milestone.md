## Findings

**C1 CRITICAL — `integration.sh:1327` (with `scratch_git`, `:643`). Under an exported `GIT_DIR`,
`--self-test` commits into the host repo.**
The #24 guard case calls `GIT_DIR=… GIT_WORK_TREE=… GIT_INDEX_FILE=… mono_fixture`. That is a
temporary assignment in front of a *function*. In bash (3.2 and 5), `unset` inside `scratch_git`
drops only that temporary scope, so the OUTER exported `GIT_DIR` shows through, and that is the one a
hook exports. So every `scratch_git` in `mono_fixture` (`init`, `config core.quotePath true`,
`add -A`, `commit`) runs against the real host. Repro: a throwaway host with one commit
(`precious.txt`), then `GIT_DIR=<host>/.git bash integration.sh --self-test`. The host gets a new
commit `2bd4919 t fixture` whose tree is the mono fixture: `precious.txt` is deleted and
`README.md` and `game/…` are added. Its config gains `quotePath = true`. The self-test reports only
1 MISS, and never the guard, because the guard inspects its own inner `host`, not the real one.
Minimal proof:
`export GIT_DIR=/outer; f(){ (unset GIT_DIR; echo ${GIT_DIR-unset}); }; GIT_DIR=/inline f` prints
`/outer`. Because of this, milestone ship criterion 1 and the diff-slice lane's third criterion are
**not met**. The pinned pre-push strips `--local-env-vars`, which narrows exposure but does not
remove it: other hook managers, Claude Code hooks, and exported shells still reach it.
Fix, both proven here: have `scratch_git` spawn `env -u GIT_DIR -u GIT_WORK_TREE -u GIT_INDEX_FILE …
git -C …` (immune to caller scoping), and/or run the guard as
`( export GIT_DIR=…; mono_fixture … )`, the shape `gdk_runners.sh:937` already uses. Then make the
guard case run under an OUTER exported host as well.

**C2 CRITICAL — `integration.sh:574` (`fixture_slice`). The referencer census misses infra, so
`--diff` under-selects (a rule-4 regression from 1.3.0).**
The files searched for fixture references are the `.gd/.tscn/.tres` under the fixture root plus the
*gate* scenarios. Infra (`scenario_base`/`scenario_runner`) and `.gd` files under the scenario dir's
own `support/` are not in that set, so the reverse closure cannot pass through them. Repro, with
`fixture_slice` extracted verbatim: `scenario_base.gd` preloads `res://tests/support/shared_map.gd`;
`alpha` also loads it directly; `beta` and `gamma` extend the base (gamma through
`tests/integration/support/helper.gd`). Touching `shared_map.gd` gives `FIXTURE … alpha` and
nothing else. `integration-diff` is in `GDK_PRECOMMIT_TIERS`, so a change that breaks beta passes
the commit gate on alpha + smoke. 1.3.0 booted the whole tier for any `tests/support/` touch.
Fix, proven here: add `find "$sdir" -type f -name '*.gd'` to the referencer list. The same repro
then selects alpha, beta and gamma. Add a self-test case for "fixture reached only through the base".

**M1 MAJOR — CHANGELOG. The #30 fix reddens `check rng` for a consumer who allowlisted or baselined
the false positive.**
A repo that worked around #30 with the documented carve-out now fails on the bump. For example,
`[rng] allowlist = { "systems/stream.gd:randf" = …, "systems/stream.gd:coin" = … }`: v1.3.0 gives
PASS with 2 allowlisted. HEAD gives `STALE systems/stream.gd:coin …` and `STALE …:randf`, exit 1.
A `baseline` count goes `SHRUNK`/`STALE` the same way. This is by design (a carve-out only shrinks)
and a devkit.toml edit, not a Makefile edit, so 1.4.0 is still a minor. But the release notes must
say: "drop `[rng]` allowlist/baseline entries that held `func randf()` declarations or a script's
own draw-named calls."

**m1 MINOR — CHANGELOG (#28 bullet) says more than the code does.** "`install-runners` … an unknown
or malformed value exits 2 there too" holds only when a retired `.github/workflows/uid-guard.yml`
exists, because the roster is read only in `retired_line`. Probe: `[checks] godot = ["uid","tress"]`
exits 0 without it and 2 with it. A bare-string value also exits 0. Reword the bullet: "when it
names a retired uid-guard.yml".

**m2 MINOR — `rng.py:108`. The shadow set also covers inner-class bodies.** An outer `func randf()`
suppresses a `randf()` inside `class Inner:`, where the unqualified name is not the outer instance
method. Probe: that file PASSes. Whether Godot resolves it to the global or refuses to compile was
NOT verified in an engine. Either way the gate says PASS without knowing.

**m3 MINOR — `integration.sh:1620`. A precheck repair that exits 2 becomes exit 1.** An
`import_cache.sh` usage/config exit 2 (not a Godot project, library missing, copy failed) is
reported as `FAIL … exited 2`, with integration exit 1. Rule 6 wants 2 passed through.

**m4 MINOR — CHANGELOG, warm bullet.** "A scenario that fails warm and passes cold prints
`WARM-ONLY`" is true only under `--diff` (`:1582`). Under `--all`/`--system` a warm failure stays
red with no cold retry. README and `--help` already say "With `--diff`", so add those words to the
bullet.

**N1 NIT.** The CHANGELOG says "run `uv lock`". `install-runners`, README and the Makefile.tiers
`$(error)` all say `uv sync`. Both work; pick one.
**N2 NIT.** `unit.sh:399`: a non-integer `GDK_UNIT_TIMEOUT` is now refused with exit 2. This new
refusal is not in the CHANGELOG.
**N3 NIT.** `ci-godot-toolchain.yml` syncs the lock whenever `uv.lock` names the kit, even when a
Makefile `GODOT_DEVKIT_VERSION` pin wins. That is harmless, but the comment's claim "the command
Makefile.tiers runs" is then untrue.

## Q2 — seams

These compose correctly, by reading `integration.sh:1679-1834`:

- A handed-back scenario has no warm row, so it is counted once, from its cold row.
- The rerun cap counts warm failures, because `FAILED_NAMES` is built from every row.
- A warm failure that passes alone is `WARM-ONLY`. A handed-back one that passes alone is `FLAKE`.
  Neither is counted twice, because a rerun adjusts PASS/FAIL and never appends a row.
- `UNREPORTED` and the warm census do not double-count (`:1803`).
- `GDK_SCENARIO_IN_SWEEP=1` is set on the cold fan-out, the warm workers and the rerun.
- The precheck's `git ls-files -- 'project.godot' '*.uid' '*.import'` matches the real census
  (8 = 8 on the fixture).
- `GIT_OPTIONAL_LOCKS=0` is exported by both `gdk_runners.sh:76` and `integration.sh:108`, with the
  same value. No conflict.
- Lock resolution agrees across `Makefile.tiers`, `install.py`, README and the CI action: the same
  `grep -qx 'name = "godot-devkit"'`, and the legacy pin wins with a warning.

## Q3 — semver and contract

No consumer Makefile or hook edit is required: the legacy pin resolves exactly as before, and
installed runners change only on `--force`. The one forced edit is M1's devkit.toml carve-outs, so
the minor bump is right if M1 is in the notes. With no devkit.toml and no new env vars, the
differences from 1.3.0 are all the documented fixes.

Output shapes consumers may grep, for the release notes:

- **integration**:
  - `SUMMARY: N passed (K flaky[, W warm-only]), …` — a regex expecting `passed,` right after the
    number breaks on a flaky run;
  - the SUMMARY census note `; warm a, cold b, handed back c`;
  - new lines: `  FLAKE  …`, `  WARM-ONLY  …`, `rerunning N failed scenario(s) alone, once each`,
    the rerun-cap line, `fixture root …: N file(s) scanned for references`,
    `fixture X selected N scenario(s)`, `fixture X is referenced by no scenario — booting the tier`,
    `import cache is stale (…) — running import_cache.sh once, before the sweep`,
    `FAIL — the import-cache repair …`;
  - warm mode: `N scenario(s), warm: …`, `cold: …`, `WALL: …`, `WARM-ABORT`.
- **unit**: `[UNIT] timeout Ns (…)` is the first line, and the HARD_TIMEOUT text names
  `GDK_UNIT_TIMEOUT`.
- **import_cache**: the banner `…, in a copy ==`; `scratch copy: …`;
  `dropped N re-serialised files (import churn): …`; the live-process `WARN`. The line
  `the pass wrote into the tree:` is gone.
- **capture**: the loop `WARN`; `previous/` rotation.
- **gdk-runners self-test**: `SKIP — …`.
- **refs**: the `dynamic (untyped receiver)` heading; `(no references found)` only when that bucket
