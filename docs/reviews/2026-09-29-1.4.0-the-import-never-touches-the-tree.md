## feature: 1.4.0/the-import-never-touches-the-tree

**Verdict: HOLD.** Two MAJORs. Both criteria are met: a killed PASS leaves the tree
byte-identical, and a full run keeps the `.tres` and brings the new sidecar back. Two problems
remain. The copy's file set is not the tree's, so the swapped cache can describe a different
project (M1). The swap's cleanup leaves a large untracked directory behind when interrupted, and
then says the tree is untouched (M2).

### Blockers

- **M1 MAJOR** `import_cache.sh:215-218`. The copy holds only tracked files plus
  untracked-not-ignored ones. Anything gitignored that Godot reads is missing from it: an addon
  installed by a plugin manager, generated scripts, `override.cfg`. The pass therefore builds a
  `.godot/` for a different project, the outcome check PASSes, and the swap installs that cache.
  Repro: the tree's `global_script_class_cache.cfg` came back as `class_name Mine` only.
  `VendoredThing` (in the gitignored `addons/vendored/`) was dropped from the registry. Before
  `041301c` the pass ran in the tree and saw that file. This is a write that looks legitimate and is
  not. Inferred with a real engine: every boot that uses the class fails to resolve it until an
  editor rescans. Fix: copy everything except `.git`, `.godot`, and the sandbox dir, which is what
  the tarball branch (`:220`) already does. A clone makes ignored bulk cheap. The brief's
  "tracked + untracked-not-ignored" wording is the thing to amend.
- **M2 MAJOR** `import_cache.sh:722-737, 625-630`. The old cache is renamed to `.godot.old.$$` BESIDE
  `.godot`, and it is `rm -rf`'d only after the signal traps are re-armed. A Ctrl-C during that rm
  (seconds on a GB cache) exits 130 and prints "the tree is as it was". It leaves
  `.godot.old.<pid>/` behind, untracked and not matched by a `.godot/` ignore rule. Reproduced:
  `git status` showed `?? .godot.old.81205/`. A `git add -A` commits the cache, and no later run
  reaps it, because each run names its own pid. Fix: `mv .godot "$COPY/.godot.old"`. That is the
  same filesystem, inside the ignored run dir: the EXIT hook removes it, and after a SIGKILL the
  next run reaps it. Also make `on_signal`'s message true once the swap has happened.

### Recorded

- **m3 MINOR** `import_cache.sh:694-703`. When the pass rewrites an EXISTING sidecar (for example,
  Godot re-minting a duplicate uid after a `.gd` and its `.gd.uid` were copy-pasted), the run drops
  it and reports it as `re-serialised files (import churn)`. The swapped `uid_cache.bin` holds the
  pass's version. Reproduced: `dropped 1 re-serialised files (import churn): scripts/mine.gd.uid`,
  with the tree at `uid://dupe` and the cache fresh. The tree and cache now disagree, and the
  report calls that churn. Fix: give changed sidecars their own line ("NOT applied; the new cache
  expects them"), or bring them back.
- **m4 MINOR** `import_cache.sh:197-208, 657`. On ext4, `cp --reflink=auto` succeeds as a full
  copy, and the census prints `(--reflink=auto)` as though the tree was cloned. A multi-GB project
  plus its `.godot/` is copied on every run, and the diff-slice precheck now triggers runs. Fix:
  print `reflink or copy`, with the bytes copied.
- **N5 NIT** `import_cache.sh:286-296`. The live-process match splits argv on whitespace, so a
  project root containing a space never matches and the WARN never prints.
- **N6 NIT** `import_cache.sh:726-731`. Two concurrent runs interleaving between the two renames
  land the second copy's `.godot` INSIDE the first's (`.godot/.godot`). The window is microseconds.
  Recorded only.
- **N7 NIT**. "Never touches the tree" holds for `make import-cache` only. `scenario.sh:582, 598`
  still run the editor pass in-tree, and the diff-slice rerun now reaches rung 2 (see that record's
  M3).
- **N8 NIT** `import_cache.sh:228`. `cp` gets no `--`, so a tracked root-level file named `-x.gd`
  is read as a flag.
