## Findings
- **m1 MINOR** src/godot_devkit/godot/installables/Makefile.tiers:55 — "locked" means only that `.venv/bin/godot-devkit` exists. Failure: a `git pull` bumps godot-devkit in uv.lock, the developer does not run `uv sync`, and local `make check` runs the stale version and prints PASS under the old gate semantics (CI syncs, so CI does not see this). Consider `uv run --frozen`/`--locked` or a version check against uv.lock.
- **m2 MINOR** Makefile.tiers:56-58 — the both-pins refusal fires on any `.venv/bin/godot-devkit`, including a legacy-pin consumer who installed the kit into its venv for other reasons (e.g. a git-sourced dev dep). The first `install-runners --force` onto 1.4.0 then makes `make` fail until they edit the Makefile. The refusal is loud and says how to fix it, and it follows the brief. Name it in CHANGELOG as a possible edit.
- **m3 MINOR** .github/workflows/release.yml:102-107 — re-dispatching a tag whose deploy failed is refused at `release` (the wheel already exists), so the index can only be rebuilt by "re-run failed jobs" or by the next release. The claim at :15-17 that the next run repairs a lost run holds only for a NEW tag. Fix: skip the build and attach steps when the wheel's hash already matches, and still run `index`.
- **m4 MINOR** release.yml:40-42 — `concurrency: release` keeps only one pending run. Failure: three tags pushed close together, and the middle run is cancelled while pending, so that version never gets a wheel. Fix: a per-tag group for `release` and a shared group only for `index`+`deploy`.
- **m5 MINOR** release.yml:102 — the re-tag refusal only sees a release that still exists. Failure: someone deletes the Release, moves the tag, and re-runs; a different wheel with the same filename is published, and every consumer's uv.lock hash breaks. Cheap guard: refuse when the live index already lists the filename.
- **W1 WARNING** release.yml:20-22 — the first deploy from a tag needs the `github-pages` environment to allow `v*` tags. The default policy may allow only the default branch. Not verifiable before the tag; the orchestrator must set it before `release`.
- **n1 NIT** release.yml:35-38 — permissions apply to all jobs. Per-job would be least privilege: `release` contents:write, `index` contents:read, `deploy` pages+id-token.
- **n2 NIT** tools/release/build_index.py:95-103 — only the test uses `--project`; `render(project=)` already covers it. It is a flag with no caller.
- **n3 NIT** build_index.py:67-83 — it does not check that an asset filename belongs to the project, and it emits no `data-requires-python`. uv reads Requires-Python from wheel metadata anyway.
- **n4 NIT** src/godot_devkit/godot/install.py:200-213 — PYPROJECT_BLOCK pins the running `__version__`. When run from an unreleased tree it prints a version the index does not carry.
