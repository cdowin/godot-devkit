Findings:
- `M1` MAJOR `src/godot_devkit/godot/read/refs.py:108-115`. `_call_emit_pattern` counts a
  receiverless `name.emit(` (`:112`), but no arm counts a receiverless `name.connect(` or
  `name.disconnect(`. `_dynamic_pattern` (`:152`) requires a leading `.`. **Failure scenario,
  run:** `ent/entity.gd` declares `signal died`, and `ent/player.gd` (`extends Entity`) has
  `died.connect(_on_died)` in `_ready`. `refs died` prints `## definitions (1)` and nothing else.
  The live subscriber is invisible, and a reviewer files the same delete finding #19 filed. When
  the declaring script is outside scope (an excluded addon), the report is
  `(no references found)`, the literal #19 output. This is the most common way to connect an
  inherited signal. It is in the defect class the feature is named for. Before, `name.emit(` was
  counted and `name.connect(` was not; this lane touched that arm and left the gap. **Fix:** add
  `rf'\b{word}\.(?:connect|disconnect)\('` to `_call_emit_pattern` (a self-reference, so a typed
  bucket, not dynamic) and one `GRAMMAR` line in `tests/test_read_verbs.py`.
- `M2` MINOR `refs.py:154`. `\bconnect\(` cannot match inside `disconnect(`. **Failure scenario,
  run:** a script whose only mention of `gone` is `e.disconnect("gone", _x)` makes `refs gone`
  print `(no references found)`, a wrong zero. The brief listed only `connect("<name>"`, and a
  disconnect-only reference is rare, so MINOR. **Fix:** `\b(?:dis)?connect\(`, in the same
  change as M1.
- `M3` MINOR (pre-existing, carry forward as its own issue) `refs.py:214-233`. `scan_scene_refs`
  reads `ext_resource` and `sub_resource` only, never `[connection signal=… method=…]`.
  **Failure scenario, run:** a signal and its handler wired in the editor. `refs pinged` and
  `refs _on_pinged` each print `## definitions (1)` only. Deleting `_on_pinged` on that evidence
  breaks the connection at runtime, with no parse error. This is a bigger surface than #19. It
  needs a scene-side scan, not a regex, so it is out of this brief. Deferred, not held.
- `M4` MINOR `src/godot_devkit/godot/checks/rng.py:106-107`. The shadow set `own` is file-wide.
  `FUNC_RE` matches an indented inner-class `func` too. **Failure scenario, run:**
  `class Inner:` / `\tfunc randi()`, then an outer `func roll(): return randi()`. `scan_text`
  returns `[]`, but the outer `randi()` is the global generator. That is a silent PASS over a
  real bare draw (rule 4, read side). It is rare, so MINOR. **Fix:** collect `own` only from
  column-0 `func` lines, or from the current class's indent.
- `N1` NIT `src/godot_devkit/cli.py:96-97`. The comment calls the import a re-export for the
  suite. But `cli.py:202` uses `KNOWN_GATES`/`OPT_IN_GATES` itself, so this is an import, not a
  layer. The two suite references (`tests/test_check_uid.py:374`,
  `tests/test_tres_canonical.py:183`) should name the owner, `godot.checks.roster`. Then drop the
  comment.
- `N2` NIT `src/godot_devkit/godot/checks/roster.py:40-42`. There is one blank line before a
  top-level `def`; PEP 8 wants two.
- `N3` NIT `refs.py:145-156`. `is_connected("name"`, `has_signal("name"` and
  `Signal(obj, "name")` fall in no bucket. They are rarely a signal's only mention. Note them in
  the docstring's scope line, or add them with M2.
