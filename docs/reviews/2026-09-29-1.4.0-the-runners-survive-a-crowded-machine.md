## feature: 1.4.0/the-runners-survive-a-crowded-machine

**Verdict: HOLD.** One MAJOR. The liveness rewrite still reads EPERM as death whenever `ps` can see
this shell but not the target. That is the named incident (two accounts share a checkout) on a
Linux host with `/proc` `hidepid`. In the same gap the self-test SKIPs the two cases that would
catch it. Everything else ships: the GIT_DIR isolation (the damage reproduces at HEAD~ and is gone
now), the timeout arithmetic, and `GIT_OPTIONAL_LOCKS`. `GIT_OPTIONAL_LOCKS=0` only drops
*optional* locks. `git add`/`commit` still take `index.lock`, and the self-test's own `git add`
runs after the export and passes.

### Blockers

- **M1 MAJOR** `src/godot_devkit/godot/installables/gdk_runners.sh:163-164`. EPERM from `kill -0`
  falls through to `ps -p "$pid"`, and the only guard is `ps -p "$$"`. Scenario: Linux with
  `/proc` mounted `hidepid=2`, and two accounts running gates in one checkout. The peer's
  `kill -0` returns EPERM. `ps` sees this shell but not the peer, so the function returns DEAD,
  and `_gdk_reap_stale_run_homes` (`:180`) runs `rm -rf` on the peer's live HOME.
  - Reproduced with stubs: kill says "Operation not permitted", ps succeeds only for `$$` → DEAD →
    "reaper DELETED the live peer home".
  - This fails ship criterion 3 as written ("live for a pid whose `kill -0` fails with anything
    but ESRCH").
  - The self-test case at `:777-780` asserts the opposite, so it proves the bug is correct.
  - The SKIP predicate (`ps -p 1`, `:758`) is not the function's blindness predicate (`ps -p $$`).
    In exactly this environment the real-pid cases SKIP while the function would fail them.
  - Not a regression: pre-change code also said dead there. It is the thing this feature exists
    to fix.
  - Fix, and it is the simpler end state: `kill -0` succeeds → live; `*No such process*` → dead;
    anything else → live. Delete both `ps` calls. kill(2) returns EPERM only for a pid it found
    (observed above under `sandbox-exec`). Flip the `:780` case to assert live.

### Also raised (do not hold)

- **m2 MINOR** `unit.sh:444`. `$((TIMEOUT_SECONDS * 2))` with a fractional explicit
  `GDK_UNIT_TIMEOUT=1.5` is a bash arithmetic error. `timeout` accepts `1.5s`, so this value
  worked before this change.
  - The error aborts the `if`, so a real hang is reported as `COVERAGE FAIL (no totals line)`,
    rc 2, with verdict FAIL and not HANG. Reproduced with a sleeping stub engine.
  - Not a PASS, but a misdiagnosis.
  - Fix: refuse a non-integer `GDK_UNIT_TIMEOUT` up front (exit 2), or double it in awk.
- **m3 MINOR** `unit.sh:185`. macOS `sysctl` localises its output. Under `LC_ALL=de_DE.UTF-8` it
  prints `{ 66,73 59,99 42,84 }`, the ERE rejects it, and the result is `load unreadable`. So
  #32's scaling never engages for comma-decimal macOS users. The fallback is honest, but the fix
  is missing for them. `:174` also prints `2,1x`. Fix: `LC_ALL=C` on `sysctl` and on both awks.
- **m4 MINOR** `gdk_runners.sh:764` and `:1008`. The SKIP is not in the census.
  - Under a sandbox the library still prints `SELF-TEST OK — N case(s)`, and
    `make runners-self-test`'s single verdict line says PASS. The two unmeasured cases exist only
    in the transcript.
  - Rule 4 says count what you did not measure: `OK — 53 case(s), 2 skipped (ps hides pid 1)`.
  - The SKIP text blames "the macOS seatbelt" even on a Linux `hidepid` host.
- **N5 NIT** `gdk_runners.sh:597-599`. The hand-kept list covers 6 `GIT_*` variables. git's
  canonical `git rev-parse --local-env-vars` has 15, and the missing ones include
  `GIT_CONFIG_PARAMETERS`/`_COUNT`, `GIT_IMPLICIT_WORK_TREE`, `GIT_SHALLOW_FILE` and
  `GIT_GRAFT_FILE`. I found none of them that routes the fixture's writes into the host.
  `unset $(git rev-parse --local-env-vars)` is the list that maintains itself.
- **N6 NIT** `unit.sh:174`. The factor is a ceiling but the "why" is rounded. Load 4.04 on 4 cpus
  prints `timeout 360s (load 1.0x)`, which reads as doubling at 1x.
- **N7 NIT** `unit.sh:402-404`. The start line is printed before `gdk_gate_log`, so it is
  console-only. The transcript under `.gate-reports/` never records the bound it ran under.
- **N8 NIT, cross-lane, for the milestone record.**
  - `integration.sh` never sources `gdk_runners.sh`, so its git reads (`:308-310`, the new
    `--diff`) do not get `GIT_OPTIONAL_LOCKS=0`. I believe `git diff <ref>` writes no index;
    not verified.
  - `integration.sh:668` still runs `cd "$mono" && git init -q .`, the #24 shape. The diff-slice
    lane owns it and is still `building`. The pinned `cc-git-allowlist` hook blocks the same text.
- **N9 NIT** `CHANGELOG.md:6-7` says pids are dead "only on positive evidence (ESRCH)", but the
  code also counts a visible table that lacks the pid. That becomes true once M1 lands. The
  grain's `changelog:` field is empty, and the release belt asks for it (this is milestone-wide).
